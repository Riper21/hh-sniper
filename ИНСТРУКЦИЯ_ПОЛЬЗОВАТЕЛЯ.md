# Инструкция пользователя hh-snpr

Бот для охоты за вакансиями на hh.ru: каждую минуту ищет свежие вакансии по
вашим запросам, оценивает их нейросетью на соответствие вашему профилю,
пишет сопроводительное письмо и откликается — вручную или автоматически.

Зачем спешить: на ходовую вакансию боты откликаются каждые ~4 секунды
(замер: 264 отклика за 18 минут). Позицию ботам не обогнать, но чем раньше
ваш отклик — тем выше в очереди. Поэтому система бьёт по вакансиям, которым
меньше 10 минут, и всегда прикладывает письмо-конверт с вашими проектами.

---

## 1. Установка (один раз)

Нужен Windows + Python 3.13.

```powershell
# 1. Клонировать репозиторий, зайти в папку
cd hh_snpr

# 2. Виртуальное окружение
python -m venv .venv

# 3. Установить базу hh-applicant-tool (она же тянет все зависимости)
.venv\Scripts\pip.exe install -e .\hh-applicant-tool

# 4. Проверить, что всё собралось (должны пройти все тесты)
.venv\Scripts\python.exe -m pytest tests -q
```

## 2. Что настраивать — обязательный минимум

### 2.1. Токен hh (один раз, ~5 минут)

```powershell
.venv\Scripts\python.exe -m snpr.hh_tool ваш@email.ru
```

Откроется браузер → вход на hh → подтвердить. Капча — вручную.
Токен сохранится в `%APPDATA%\hh-applicant-tool\auth.json`, живёт ~14 дней
и продлевается автоматически. Проверка здоровья:

```powershell
.venv\Scripts\hh-applicant-tool.exe whoami
```

### 2.2. Доступ к нейросети — файл `.env` в корне проекта

Скопируйте заготовку и заполните:

```powershell
Copy-Item .env.example .env
```

```ini
SNE_AI_BASE_URL=https://ваш-endpoint/v1
SNE_AI_MODEL=название-модели
SNE_AI_API_KEY=ваш-ключ
```

Любой OpenAI-совместимый шлюз. Ключ только сюда — не в командную строку,
не в git.

### 2.3. `snpr\config.toml` — главный файл настроек

Всё, что отличает «вас» от «другого человека», лежит здесь. Правите файл —
через минуту (на следующем такте) уже работает. Ничего перезапускать не надо.

**Важно:** в чистой установке все персональные значения — ЗАГЛУШКИ-ПРИМЕРЫ
(«Иван Примеров», github.com/example-user). Пока не заменили их на свои —
боевой режим не включайте.

**Обязательно поменять под себя — 5 вещей:**

| Раздел | Ключ | Что это | На что влияет |
|---|---|---|---|
| `[scoring]` | `profile` | Кто вы: грейд, стек, деньги, гео, анти-паттерны | Нейросеть оценивает каждую вакансию ИМЕННО по этому профилю. Хотите другие вакансии — меняйте это |
| `[search]` | `queries` | Слова полнотекстового поиска hh | Какие вакансии ищем вообще |
| `[letter]` | `static_text` | Текст письма работодателю | Что реально уходит с откликом |
| `[letter]` | `profile` | Факты о вас с цифрами | Числа из письма проверяются по этим фактам (см. п. 4) |
| `[letter_guard]` | `allowed_url_prefixes` | Ваши ссылки | Какие github/статьи разрешены в письме |

Пример `[scoring].profile` (пишите о себе честно и конкретно):

```toml
profile = '''- Senior/Lead инженер: ваша специализация и главная экспертиза
- Основной стек: ваши языки и технологии
- Грейд: какие роли рассматриваете (мидловые/джуновые — если нет)
- Формат: ваш город / удалёнка / релокация
- Деньги: ориентир от N на руки (нижняя граница интереса)
- Анти-паттерны: что заведомо НЕ рассматриваете'''
```

В `static_text` напишите своё имя, свои проекты и ссылки. Числа в письме
(«5 лет», «200+ ТЗ») должны совпадать с фактами в `[letter].profile` — иначе
гвард отправит письмо на ручную проверку вместо автопилота (это защита от
галлюцинаций нейросети, см. п. 4).

## 3. Как это работает (что происходит каждую минуту)

```
поиск hh ──► дедуп (видели?) ──► жёсткий гейт ──► LLM-скоринг 0-100
                                                    │
                     ┌──────────────────────────────┤
                     ▼                              ▼
             скор 45-54 ИЛИ старше 10 мин     скор >= 55 И свежее 10 мин
                     │                              │
                ПАРКОВКА                       АВТОПУСК
         (окно "approve" + звук:                (письмо + отклик
          y = откликнуть,                       уходит сразу)
          n = пропустить,
          e = поправить письмо)
```

- **Скор 0-100** ставит нейросеть по вашему профилю. Ниже 45 — вакансию
  пропускаем, письмо не пишем.
- **Свежесть**: автопилот пускает только по вакансиям младше 10 минут.
  Просмотры hh не лимитированы, лимит только на отклики — поэтому смотрим
  каждую минуту, а пускаем избирательно.
- Пускы логируются в `data\applied.jsonl` — всегда видно, куда уже откликнулись.

## 4. Гвард письма (почему нельзя писать в письме что попало)

Перед автопилотом письмо проверяется автоматически:

- **числа** в письме должны быть из `[letter].profile` или из вилки зарплаты
  этой вакансии (нельзя отправить работодателю цифру, которой нет в ваших фактах);
- **ссылки** — только с разрешённых префиксов (`[letter_guard]`).

Нарушение → письмо уходит на ручную проверку, автопилот не пускает. Это
страховка: если когда-нибудь включите LLM-генерацию писем, гвард не даст
нейросети выдумать цифры или чужие ссылки. **Меняя письмо — меняйте и факты.**

## 5. Запуск

### Первый раз — обязательно всухую

```powershell
.venv\Scripts\python.exe -m snpr sne --dry-run
```

Прогон без реальных откликов: видно, что ищется, что скорится, какие письма.
Убедились, что не пускает по ерунде — включайте боевое.

### Постоянный режим — джоба

```powershell
.venv\Scripts\python.exe -m snpr job on     # включить (задача hh-snpr, каждую минуту)
.venv\Scripts\python.exe -m snpr job status # состояние
.venv\Scripts\python.exe -m snpr job off    # выключить (включение — одной командой обратно)
.venv\Scripts\python.exe -m snpr job log    # хвост журнала
```

Джоба работает скрыто (консоль не мигает). Когда накопятся вакансии на
решение — сам откроется окно `approve` и прозвучит сигнал. Ноутбук спал и
проснулся — первый же такт доберёт всё пропущенное.

Можно мышкой — файлы в корне проекта: `Статус_Джобы.cmd`,
`Включить_Джобу.cmd`, `Выключить_Джобу.cmd`, `Прогон_Сейчас.cmd`,
`Лог_Джобы.cmd`.

**Linux/macOS** (джобы Task Scheduler нет): тикер — `python -m snpr daemon`
(Ctrl-C — стоп), `job on` подскажет установку автозапуска юнитом ОС:

```bash
bash scripts/unix/install.sh   # Linux: systemd user-timer; macOS: launchd
```

### Постоянный режим — VPS: Docker, 24/7

Ноут можно закрыть совсем: конвейер тикает в контейнере на любом
дешёвом сервере (1 vCPU / 1 ГБ хватает). Docker сам рестартует контейнер
и поднимает его после ребута VPS.

Один раз переносится токен (авторизация нужна ТОЛЬКО на машине с
браузером — на VPS она не нужна):

1. На десктопе, где уже авторизованы: взять `%APPDATA%\hh-applicant-tool\`
   — файлы `auth.json` и `cookies.txt` (Linux/macOS: `~/.config/hh-applicant-tool/`).
2. На VPS: клонировать репо, создать папки `hh-config` и `data`
   (`mkdir -p hh-config data` — именно руками: Docker создал бы их от
   root, и контейнер не смог бы писать), положить в `hh-config` оба файла.
3. Рядом — `.env` с доступом к нейросети (как в п. 2.2: `SNE_AI_BASE_URL`,
   `SNE_AI_MODEL`, `SNE_AI_API_KEY`; без LLM — просто пустой файл `.env`).
4. Запустить:

```bash
docker compose up -d --build
```

Всё состояние живёт снаружи образа (переживает пересборку и обновление):
`./data` — история и лог тика, `./hh-config` — токен. Токен живёт ~14 дней
и продлевается сам во время тиков — надолго хватает, слетит (403) только
при выходе из всех сессий на hh.

Работа с контейнера:

```bash
docker compose exec hh-snpr python -X utf8 -m snpr job status  # живой статус
docker compose exec hh-snpr python -X utf8 -m snpr job run      # такт руками
docker compose exec hh-snpr python -X utf8 -m snpr job log      # хвост лога
docker compose exec hh-snpr python -X utf8 -m snpr approve      # разбор парковки
docker compose logs -f hh-snpr                                  # лог демона (BEL = есть на approve)
```

У контейнера есть HEALTHCHECK: тик каждую минуту трогает маркер
`data/last_run.txt`, и если он протух на 3+ часа (авторизация, сеть) —
контейнер помечается `unhealthy`: `docker ps` сразу покажет.

Если в логах `Permission denied` (на VPS вошли по ssh под root, а
контейнер работает от пользователя 1000) — один раз дать томам права:

```bash
sudo chown -R 1000:1000 data hh-config
```

### Окно approve

Когда откроется — по каждой вакансии: прочитать скор, причины, письмо;
`y` = откликнуть, `n` = пропустить, `e` = поправить письмо и откликнуть.
Вакансия из окна никуда не денется: сбой или закрытие окна — она останется
в парковке до следующего раза.

## 6. Настройки «подкрутить» — опционально

Все в `snpr\config.toml`, эффект с следующего такта:

| Ключ | Дефолт | Что делает | Когда менять |
|---|---|---|---|
| `[scoring] maybe_min` | 45 | С какой оценки писать письмо и парить | Мало откликов — снизить, много мусора — поднять |
| `[scoring] auto_approve_min` | 55 | Порог автопилота | **0 = автопилот выключен**, всё на ручное решение |
| `[scoring] target_min` | 75 | Порог «мечта» | Обычно не трогать |
| `[send] max_age_minutes` | 10 | Максимальный возраст вакансии для автопилота | Меньше = агрессивнее |
| `floor_net_rub` | 200000 | Жёсткий пол зарплаты: ниже — даже не скорим | Ваша нижняя граница |
| `[scoring] workers` | 4 | Параллельность LLM | 8 ловит ограничение API — не поднимать |
| `[search] max_scored_per_run` | 100 | Бюджет нейросети на такт | Лишнее копится в очередь, не теряется |
| `[grade]/[vendor]/[gov]/[geo] enabled` | false | Жёсткие гейты-списки | Выключены: «вендорность» решает скоринг |
| `[nanny] silence_days` | 3 | Дней тишины до «повис» в отчёте няни | Зависания ловить раньше — уменьшить |
| `[raise] enabled` / `interval_hours` / окно | true / 4 ч / 9–19 МСК | Автоподнятие резюме | Меньше 4 ч бессмысленно (лимит hh); `enabled = false` — выключить буст |
| `[cleanup] older_than_days` | 14 | Порог «неактивности» отклика для уборки | Аккуратнее — уменьшить |
| `[blacklist] file` | `data/blacklist.txt` | Файл чёрного списка работодателей | Редко нужно менять |

Каденция джобы (раз в минуту) в config.toml НЕ находится — это параметр
плановой задачи Windows: `scripts\register_task.ps1` или Панель управления →
Планировщик.

## 7. Куда смотреть, что происходит

| Файл | Что в нём |
|---|---|
| `data\scheduler.log` | Журнал тактов (поиск, скоринг, решения) |
| `data\applied.jsonl` | **Все пускы**: вакансия, скор, письмо, время |
| `data\parked.jsonl` | Очередь на ваше решение |
| `data\scores.jsonl` | История оценок (видно, что и почему отсеялось) |
| `data\deferred.jsonl` | Не успели проскорить — вернётся в следующих тактах |
| `data\nanny.jsonl` | Снапшоты откликов для няни (диффы между прогонами) |
| `data\last_raise.txt` | Маркер последнего поднятия резюме |
| `data\replied.jsonl` | История автоответов в чатах (анти-дубли) |
| `data\blacklist.txt` | Чёрный список работодателей (создаётся `blacklist add`) |

Разобрать конкретную вакансию руками:

```powershell
.venv\Scripts\python.exe -m snpr why 123456789        # по id
.venv\Scripts\python.exe -m snpr why https://hh.ru/vacancy/123456789
```

## 8. После отклика: няня, автоподнятие, автоответы, уборка, блэклист

Отклик ушёл — дальше пять механизмов. Автоподнятие и автоответы в чатах
работают сами, остальные — ручные команды, по умолчанию ничего не меняют.

### Няня — что происходит с моими откликами

```powershell
.venv\Scripts\python.exe -m snpr nanny
```

Читает ваши отклики (GET /negotiations) и показывает **движение** с
прошлого просмотра: ответы работодателей, просмотры резюме, смены
статусов. Снапшоты — `data\nanny.jsonl`, в отчёте только разница. Отклик
без движения дольше `silence_days` (3 дня) подсвечивается как «повис».

### Автоподнятие резюме

Работает само, отдельной команды не нужно: в каждый такт бот тихо
поднимает резюме (POST /resumes/{id}/publish), если прошло 4 часа
(минимальный интервал hh) и сейчас рабочие часы 9–19 МСК — ночью резюме
никто не листает, буст сгорает впустую. Ранжирование hh учитывает
свежесть поднятия — это бесплатный буст видимости. Сбой хука не роняет
такт. Маркер — `data\last_raise.txt`.

Ручное поднятие:

```powershell
.venv\Scripts\python.exe -m snpr raise            # с уважением к окну и интервалу
.venv\Scripts\python.exe -m snpr raise --force    # сейчас, мимо окна и маркера
```

### Автоответы на вопросы в чатах

После отклика работодатель часто присылает в чат анкету ИИ-скринера:
«Готовы ли к релокации?», «Укажите зарплату» — с кнопками вариантов.
Отклик не движется, пока на них не ответить. Отвечает бот:

```powershell
.venv\Scripts\python.exe -m snpr reply --dry-run    # посмотреть, что ответит
.venv\Scripts\python.exe -m snpr reply              # отправить
```

Правила безопасности:
- **Кнопки анкет** — вариант отправляется только при точном совпадении
  с предложенным: LLM выбирает из списка, мимо варианта — не отвечаем.
- **Текст ботам** — генерация строго из фактов `[letter].profile`, перед
  отправкой тот же LetterGuard, что и для писем: чужие ссылки, телефоны
  и числа не уйдут.
- **Люди-рекрутеры** — по умолчанию не отвечаются: их вопросы только
  показываются в отчёте (меняется `--answer-humans` / `[reply].answer_humans`).
- **Анти-дубли** — один ответ на одно сообщение (`data\replied.jsonl`);
  переписки длиннее 20 сообщений и вопросы старше 3 дней остаются вам.

Автоматика: раз в 15 минут хук такта снпрера проверяет непрочитанные
чаты и отвечает по тем же правилам. По умолчанию выключено — сначала
погоняйте `reply --dry-run` на своих чатах, потом включайте
`[reply].enabled = true` в `snpr\config.toml` (там же — интервал,
период свежести, потолок ответов за прогон).

### Уборка — снять неактивные отклики

```powershell
.venv\Scripts\python.exe -m snpr cleanup              # сухой прогон: только показать список
.venv\Scripts\python.exe -m snpr cleanup --apply      # реально снять
```

Снимает: отказы работодателя (discard) и отклики без движения дольше
`older_than_days` (14 дней). Приглашения, созвоны и офферы **не трогает**.
`--with-decline-message` — отправить работодателю сообщение при снятии
(по умолчанию тихо), `-v` — показать и оставленные отклики с причиной.

### Блэклист работодателей

Локальный файл `data\blacklist.txt` (не через API hh): строка на
работодателя — числовой id, имя или «id имя»; `#` — комментарий. Нет
файла — гейт не работает. Вакансии чёрного списка отклоняются **до
скоринга**, нейросеть на них не тратится.

```powershell
.venv\Scripts\python.exe -m snpr blacklist list
.venv\Scripts\python.exe -m snpr blacklist add 123456789
.venv\Scripts\python.exe -m snpr blacklist add https://hh.ru/vacancy/123456789
```

`add` берёт работодателя из карточки вакансии и дописывает в файл,
дубликаты не создаёт. Действует со следующего такта. «Выключить» —
очистить файл.

## 9. Важно знать

- **Правка config.toml не требует перезапуска** — следующий такт подхватит.
- **Прежде чем менять пороги вниз** (автопилот от 45) — прогоните
  `--dry-run` и посмотрите `data\scores.jsonl`, что именно вы начнёте отправлать.
- Отклики на hh ограничены (порядка 200/день) — автопилот с порогом 55 и
  гейтом 10 минут тратит их экономно. Просмотры не лимитированы.
- Токен hh живёт ~14 дней, продлевается сам. `whoami` отвечает 403 —
  значит сессия отозвана (выход из всех сессий на hh, смена пароля),
  переразлогиньтесь по п. 2.1.
- Вести под учёткой hh во время охоты ничего постороннего не стоит:
  токен и сессия лежат в открытом виде в `%APPDATA%\hh-applicant-tool\`.
- Полное удаление джобы: `Unregister-ScheduledTask hh-snpr`.
