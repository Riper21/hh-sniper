# hh-snpr

[![CI](https://github.com/Riper21/hh-sniper/actions/workflows/ci.yml/badge.svg)](https://github.com/Riper21/hh-sniper/actions/workflows/ci.yml)

**Windows / Linux / macOS / Docker (VPS, 24/7)** — четыре способа тикать:
джоба Task Scheduler (Windows), systemd user-timer (Linux), launchd (macOS),
контейнер с рестартом (Docker/VPS). Общий тикер — `python -m snpr daemon`.

Две системы в одном конвейере:

- **Снайпер (hh.ru)**: каждую минуту ищет свежие вакансии по вашим запросам,
  отсекает мусор дешёвыми правилами, скорит выживших LLM на соответствие
  вашему профилю и откликается — автопилотом по совсем свежим (младше
  10 минут; на ходовые вакансии боты откликаются каждые ~4 секунды) или
  через парковку с человеческим решением.
- **Outreach (прямые контакты)**: находит email найм-менеджеров и
  ML-команды целевых компаний (коммиты GitHub, карьер-сайты, Хабр),
  скорит их вакансии тем же профилем и подсказывает прямой контакт к
  вашим откликам. Письма автоматически НЕ отправляются.

## Архитектура: как это всё работает

### 1. Такт снайпера (каждую минуту, один процесс)

`snpr sne` — функция `run_sne` в `snpr/sne.py`. Всё внутри одного тика,
каждый блок — «тихий хук» в try/except: сбой одного не роняет остальных.

```
ПЛАНИРОВЩИК (Task Scheduler │ systemd │ launchd │ Docker │ daemon)
   │
   ▼
1. ХУКИ ДО ПОИСКА ─── автоподнятие резюме (раз в 4ч, окно 9-19 МСК)
   │                  автоответы в чатах hh (кнопки/LLM+гвард)
   │                  разбор кнопок Telegram («Пустить» = snpr approve)
   ▼
2. ПОИСК hh ────── 6 запросов, адаптивное окно (ноут спал → доберёт)
   │               дедуп: seen/applied/parked + (название, работодатель)
   ▼
3. ПРЕДФИЛЬТР (дешёвые правила, ДО LLM — snpr/filters.py)
   │   [title]  ≥1 токен роли в названии (ai/ml/ии…); стоп-слова
   │             профессий (врач/HR/SMM…); «5+ лет» из текста
   │   [grade]  джунов режет (regex названия + experience API)
   │   [salary] пол зарплаты: верх < floor или низ < 0.5·floor
   │   [blacklist] работодатели из data/blacklist.txt
   │   → выжившим — ленивая загрузка полной карточки (только им!)
   ▼
4. LLM-СКОРИНГ 0-100 (snpr/scoring.py, волны по числу воркеров,
   │               бюджет на тик, 429 → fast-fail, сторы не трогаем)
   │               профиль кандидата — [scoring].profile
   ▼
   ├─ 45-54 ИЛИ старше 10 мин ──► ПАРКОВКА (data/parked.jsonl)
   │                               окно approve + звук / кнопки TG:
   │                               y=отклик, n=пропуск, e=правка письма
   ▼
   └─ ≥55 И свежее 10 мин ─────► АВТОПУСК: письмо + отклик сразу
                                  письмо статическое + ГВАРД
                                  (числа только из профиля фактов,
                                  ссылки только из белого списка —
                                  промпт-инъекция не пройдёт)
   │
   ▼
5. ХУКИ ПОСЛЕ ── карточки итогов в Telegram
                ХАБР-РАДАР (RSS → префильтры → LLM → карточка со ссылкой)
                OUTREACH-ПОДСКАЗКА: новым откликам — прямой контакт из базы
                SIDECAR-UI: веб-интерфейс 127.0.0.1:8765 жив (упал → поднять)
```

### 2. Модуль outreach (ручные прогоны + хук подсказок)

`python -m snpr outreach <шаг>` — каждая команда идемпотентна, данные в
`data/outreach/` (gitignored). Схема сторов:

```
companies.tsv ──► orgs.jsonl ──► people.jsonl ──┐
(целевые      (резолв GitHub  (email ML-команд  ├──► outreach.jsonl
 компании)     оргов)          из коммитов)     │     (единая база
                                                │      контактов)
карьер-сайты: Alfa API, HuntFlow, Сбер (sitemap+SSR), ──┤
               Авито, Ozon (закрыт) → career_managers.jsonl
Хабр: авторы ML-хабов → Telegram → habr_crawl_pilot.jsonl ┘

outreach score: LLM-скоринг карьер-вакансий профилем снайпера
                (скор/вердикт/причины в ту же запись)
outreach base:  сборка единой базы (дедуп по contact_key)
outreach report: MD-отчёты в data/outreach/reports/
```

В тик снайпера outreach попадает только **подсказкой** (блок 5): новый
отклик в компании X → в базе есть прямой контакт → карточка в TG
«кому писать напрямую». Роль конфигурируется: `[outreach].role_keywords`
(QA/фронт/DevOps подставляют свой словарь вместо ML-дефолта).

### 3. Веб-интерфейс (127.0.0.1:8765)

Sidecar-процесс, живёт рядом с джобой (тик следит, упал — перезапустит).
Ярлык `UI_Снайпер.cmd` — двойной клик.

| Вкладка | Что |
|---|---|
| Дашборд | метрики базы, компании, свежесть |
| Контакты | база с фильтрами, источниками, верификацией |
| Каналы | вердикты каналов (почему карьер-сайты, а не hh) |
| Скоринг | hh + карьер-вакансии вместе: скор/причины/менеджер |
| Настройка | мастер: вставьте резюме → LLM-черновики профилей → config.toml (whitelist-ключи, бэкап, roundtrip-валидация) |
| Джоба | статус/включить/выключить/прогнать такт из браузера |

### 4. Конфигурация (один файл, перечитывается каждый тик)

`snpr/config.toml` — вся персонализация. Ключевые секции:

| Секция | Что |
|---|---|
| `[scoring].profile` | кто вы (для LLM-скоринга): роль, стек, грейд, деньги |
| `[search].queries` | поисковые запросы снайпера |
| `[title]` | токен-гейт названия: include/exclude/стаж |
| `[letter]` | текст письма + капсула фактов (гвард разрешает числа только отсюда) |
| `[scoring].auto_approve_min` | порог автопилота (55; 0 = всё в парковку) |
| `[send].max_age_minutes` | свежесть для автопуска (10) |
| `[outreach].role_keywords` | роль outreach (пусто = ML/AI-дефолт) |

Или не трогайте конфиг: мастер в UI составит черновики из резюме.

## Быстрый старт

Подробно — [ИНСТРУКЦИЯ_ПОЛЬЗОВАТЕЛЯ.md](ИНСТРУКЦИЯ_ПОЛЬЗОВАТЕЛЯ.md). Коротко:

```powershell
# 1. Окружение
python -m venv .venv
.venv\Scripts\pip.exe install -e .\hh-applicant-tool

# 2. Ключи: скопируйте .env.example в .env, заполните (LLM, опц. TG/GitHub)
Copy-Item .env.example .env

# 3. Токен hh (один раз, браузер + код из письма)
.venv\Scripts\python.exe -m snpr.hh_tool ваш@email.ru

# 4. Настройка под себя: config.toml — или через мастер в UI
# 5. Сухой прогон (без реальных откликов)
.venv\Scripts\python.exe -m snpr sne --dry-run
# 6. Включить минутную джобу
.venv\Scripts\python.exe -m snpr job on
```

Linux/macOS — те же команды без `.exe`; `job on` подскажет systemd/launchd
(`scripts/unix/install.sh`). VPS 24/7: `docker compose up -d --build`.

## После отклика (жизнь цикла)

- **Автоподнятие** (сам): резюме вверх раз в 4ч в рабочие часы. Ручное
  `snpr raise [--force]`;
- **Няня** (`snpr nanny`): движение по откликам — ответы, просмотры,
  статусы; только разница между прогонами. **Планирование шагов**:
  `snpr nanny <id> Позвонить в пятницу` — блок «СЛЕДУЮЩИЕ ШАГИ» с дедлайнами;
- **Ответы в чатах** (`snpr reply`): ИИ-скринеры — кнопки точно, свободный
  текст LLM строго из фактов + гвард; люди — вручную. Анти-дубль + каденция;
- **Уборка** (`snpr cleanup`): отзыв зависших (14 дней без движения),
  по умолчанию dry-run;
- **Блэклист** (`snpr blacklist add <vacancy_id>`).

## Безопасность (почему это не «накрутчик»)

- LLM используется **только для скоринга** — письмо статическое, текст не
  подгоняется под вакансию; гвард перед каждым автопуском проверяет числа
  (только из вашего профиля фактов) и ссылки (только из белого списка):
  промпт-инъекция из описания вакансии физически не может изменить письмо;
- скоринг и гейты отсекают нецелевые вакансии **до** отправки;
- письмо с каждым откликом — отклик без сопроводительного не уходит;
- официальном API hh от лица вашей учётки, договорённости hh не нарушаются.
