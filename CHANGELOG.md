## [06.11.2026] — Outreach: интеграция изолированного прогона в модуль

Изолированный research/outreach_mvp (5 итераций, 03–05.11, 11 скриптов,
sys.path-хаки, дубли хелперов, секреты в коде, ноль тестов) стал полноценным
модулем `snpr/outreach` по ПЛАН_ИНТЕГРАЦИИ_OUTREACH.md (аудит 06.11).
Критерии готовности ПРОЕКТ_ПРОГОНА §6 выполнены и зафиксированы —
контракт «outreach.jsonl + сверка со снайпером + вакансия-триггер» реализован.

### Добавлено
- **Пакет `snpr/outreach`**: единый HttpClient (кэш sha1+TTL+негатив,
  retry/backoff-лестницы, SSL-режимы, prune — 3 копии _ssl_context и 5
  лестниц research сведены в одну точку), JsonlStore с upsert-конвенцией
  (атомарность tmp-replace по образцу сторов снайпера), CampaignLog.
- **Адаптеры каналов** (порты research поверх фундамента): GitHub
  (коммиты→email, инсайт прогона сохранён), Habr (краул/матч/мост — ОДНА
  копия парсера вместо двух), career/{alfa,huntflow,jobtoo} (бандл jobtoo
  с авто-дискаври — хэш URL больше не протухает), hh — через ЕДИНУЮ точку
  входа `snpr.hh_tool.api_client`.
- **CLI**: `python -m snpr outreach seed|orgs|people|habr|match|bridge|hh|
  career|base|report|status|migrate|prune|ui` — паттерн подкоманд сиблингов.
- **Единая база `outreach.jsonl`**: роли hiring_manager/ml_team/expert,
  дедуп contact_key, ручные поля (verified, campaign) не затираются.
- **Тихий хук в тике снайпера** (шаблон maybe_habr_radar): новые отклики →
  TG-карточка-подсказка с прямым контактом и провенансом. Письма НЕ
  отправляются (notify_only). Выключен по умолчанию — включать после
  ручной верификации базы в UI.
- **Локальный UI** (`snpr outreach ui`, 127.0.0.1:8765): stdlib http.server
  + vanilla JS, ноль зависимостей — дашборд, контакты с фильтрами и
  провенанс-ссылками, полный цикл верификации карточки (критерий ≤1 мин),
  вкладка «Каналы» — вердикты АУДИТ_КАНАЛА как живой view, события кампании.
- **Секция `[outreach]`** в config.toml (8 подсекций, консервативные
  дефолты); данные — data/outreach/ (gitignored, «данные под замком»).
- **`outreach migrate`**: перенос 8 сторов+TSV+кэша(642) из research со
  сверкой счётчиков с эталоном аудита — СОВПАДЕНИЕ (36/100/893/35/53/19/
  707/38); research/ заморожен архивом (АРХИВ_ЗАМЕТКА.md).

### Безопасность
- **Android-креды hh удалены из кода** (hh_managers.py research держал
  client_id/secret в исходнике) — в env/единой точке hh_tool; CI-гвард
  на регресс (test_repo_hygiene).
- **GitHub PAT ротирован** (лежал в plaintext в research/.env), единый
  корневой .env.
- **TLS верифицируется по умолчанию**: unverified (был вшит в career/
  jobtoo research — MITM-уязвимость) — только явный insecure_tls.

### Изменено
- sne.py: хук outreach в конце такта (try/except, «прогон не задет»).
- cli.py: регистрация подкоманды outreach.

**495 тестов** (было 356 в baseline; +139 модульных; 15 pre-existing
падений habr_radar/chat_reply/cleanup — задокументированы, вне скоупа).

## [19.10.2026] — Харднинг — `6ccd876`

### Исправлено
- **Плодящиеся окна approve.** Тикер искал окно по заголовку через `tasklist`
  — и не находил его, когда окно живёт в Windows Terminal: каждую минуту
  открывалось новое, по одной и той же вакансии до пяти вопросов подряд.
  Теперь окно держит pid-лок `data\approve.lock`: второе не откроется, пока
  живо первое; мёртвый лок (криз/перезагрузка) снимается автоматически.
- **Двойные отклики на «одну» вакансию.** Работодатели иногда размещают одно
  объявление дважды (разные id, одно название). Теперь дедуп по ключу
  «название + работодатель»: за всю историю — ровно один отклик; из дублей
  одного прогона отправляется лучшая по скору, дубль из парковки закрывается
  молча, без вопроса и без письма.
- **Скоринг в шторме 429.** Rate limit от LLM-провайдера больше не вешает такт
  на ретраях: fast-fail сразу, сторы целы, следующий такт (через минуту)
  поднимается чистым.

### Изменено
- Статическое письмо — позиционирование AI-инженера (evals, LLM-as-a-Judge,
  агенты, артефакты); дефолт профиля скоринга в коде приведён к боевому
  (ваш профиль по-прежнему живёт в `config.toml`, код не трогается).

**321 тест.**

## [18.10.2026] — Автоответы в чатах hh — `4b4fdf5`

### Добавлено
- Автоответы на вопросы ИИ-скринеров в чатах работодателей: кнопки —
  только точное совпадение, свободный текст — LLM, заземлённая на капсулу

  вручную.
- `data\replied.jsonl` — анти-дубли ответов (один ответ на одно сообщение).
- CLI `python -m snpr reply` + автоматический хук в такт.

**278 тестов.**

## [18.10.2026] — Жизненный цикл отклика — `622ae08`

### Добавлено
- «Няня» — отчёт о реакциях работодателей: тишина N дней = отклик «повис».
- Автоподнятие резюме каждые 4 ч в окне 9–19 МСК (hh ранжирует по свежести).
- Уборка неактивных откликов (dry-run по умолчанию).
- Локальный блэклист работодателей.

### Переименовано
- hh-sniper → **hh-snpr**: контент-фильтр LLM-провайдера ложно срабатывал
  на слово «sniper».

**240 тестов.**

## [18.10.2026] — Первый публичный релиз — `62f8bab`, `a95c38d`

Ядро конвейера (боль: 264 ручных отклика, на ходовые вакансии боты
откликаются каждые ~4 секунды — место в очереди решает скорость):

- Живой поиск каждую минуту по ключевым словам; адаптивное окно — ноут
  спал, первый такт добирает пропущенное.
- Дедуп выдачи и жёсткий гейт по зарплате (пол — ниже даже не скорим).
- LLM-скоринг 0–100 с вердиктами и причинами; LLM используется только
  для скоринга.
- Статическое письмо + **LetterGuard**: числа в письме — только из капсулы
  фактов профиля, ссылки — только из белого списка; промпт-инъекция
  физически не может изменить текст.
- Парковка 45–54 (окно approve: `y`/`n`/`e` + звук) и автопилот 55+
  для вакансий младше 10 минут.
- Windows Task Scheduler: скрытая джоба, лок на повторный такт.
- Вендор-снапшот `hh-applicant-tool` — API-слой и авторизация hh.
